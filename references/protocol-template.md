# 模板：01-交接流程与启动指令.md

> 用法：放在包根。**这是"怎么把包交出去"的操作手册**，也是"不想每次重写提示词"的答案所在（§D 直接复制即可）。

---

```markdown
# 01-交接流程与启动指令

## A. 交付方式（按接收方场景三选一）

| 场景 | 做法 | 备注 |
| --- | --- | --- |
| 同一台机器 / 共享盘 | 直接给目录路径，**不必解包** | 最省事 |
| 传到 Linux/远程机 | `scp <包>.tar.gz user@host:/data/` → `ssh` → `tar -xzf` → `sha256sum -c MANIFEST-SHA256.txt` | Windows 自带 tar 亦可解 |
| 交给另一个 AI / 会话（无共享盘） | 把归档放到对方可访问位置，**并把 §D 启动指令整段粘贴** | 对方读不到你的聊天记录 |

> ⚠️ 最常见的失败：**只发归档、不发启动指令**。

## B. 发送方必须口头交代的 N 件事
1. <哪些东西未验证（未编译/未实测）>
2. <是否已向外部系统提交/推送：已做 / 未做>
3. <规则或硬约束：截止时间、名额、格式、不可做的事>
4. <包内副本的局限：浅克隆 / 子模块 / 缺历史，及补齐命令>
5. <优先顺序：先做什么，为什么>

## C. 接收方开局自检（1 分钟）
```bash
tar -xzf <包>.tar.gz && cd <包目录>
sha256sum -c MANIFEST-SHA256.txt | tail -3     # 期望：全 OK
# 若含 git 副本：
cd src-<repo> && git log --oneline <base>..<branch> | wc -l   # 期望：<提交数>
git status --porcelain | wc -l                                # 期望：0
git bundle verify ../<branch>.bundle                          # 期望：is okay
```
任一条不符 → 先别往下做，回报差异。

## D. 给下一个 AI 的启动指令（整段复制，替换 <占位符>）
```text
[角色] 你是 <项目名> 的接手 AI。项目根目录：<绝对路径>
[第一步·必读] 依次读，不要跳：1) 00-先读我.md  2) <交接文档>  3) <主报告>  4) <操作手册>
[当前状态] <已完成什么 / 什么是未验证的 / 是否已提交>
[环境] <机器/依赖/前置命令，如 source set_env.sh>
[按序执行] 1) <命令>  —— <为什么>；2) <命令>；3) <命令>；4) <判读标准与决策>
[硬性禁止] 未经确认不要 push/改主干/开 PR；不要 <已知错误做法>；不要 <规则禁止项>
[交付格式] 每步回报四件套：命令 / 原始日志路径 / 结论（达标或不达标）/ 下一步计划
```

## E. 交接确认清单（双方打勾）
- [ ] 归档与 SHA256 核对一致
- [ ] 接收方 §C 自检全通过
- [ ] §B 全部事项已说明
- [ ] §D 启动指令已发送（不是只发了包）
- [ ] 接收方确认第一个动作与预计完成时间
- [ ] <环境相关：算力/窗口/账号>

## F. 若交接对象是"人"而不是 AI
把 §D 换成三句话：先读哪两份文件；先跑哪条命令；把什么结果填回哪张表。
```

---

## 填写规则

| 段 | 硬要求 |
| --- | --- |
| §B | 每条都要能回答"不说会怎样"；没有后果的别写 |
| §D `[角色]` | 必须给**绝对路径**（接手方的工作目录可能不同） |
| §D `[当前状态]` | **必须显式写"未验证 / 未提交"**，否则接手方默认已完成 |
| §D `[按序执行]` | 命令级可复制；每条附一句判读标准（达标/不达标怎么办） |
| §D `[硬性禁止]` | 至少覆盖：未经确认的 push/PR、已知失效的命令、会产生无效提交的做法 |
| §D `[交付格式]` | 固定"四件套"，让进展可验证 |
| 全文 | 不许留 `<...>` 未替换 |
