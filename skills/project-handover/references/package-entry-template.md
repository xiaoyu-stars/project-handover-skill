# 模板：00-先读我.md（包内入口）

> 用法：放在包根，作为**第一个被打开的文件**。它的职责只有三件：指路、给最短上手路径、**说清边界**。

---

```markdown
# 先读我 — <项目名> 交付包

> 👉 **要把这个包交给别人 / 下一个 AI：直接看 `01-交接流程与启动指令.md`** —— 交付方式、必须交代的事项、接收方自检、可复制的启动指令。

**打包时间**：<YYYY-MM-DD>
**对象**：<目标仓库/系统> @ `<commit/版本>`
**依据**：<任务/活动/规范链接>
**截止**：<日期 时间>　｜　<其他硬约束（名额、评审期）>

> ⚠️ <本包中哪些东西尚未验证>；接手方第一件事是 <验证命令>。
> ⚠️ 本包**不含** <外部系统> 的提交/推送；<已做/未做>。

---

## 一、包里有什么

| 目录 | 内容 |
| --- | --- |
| `00-先读我.md` / `01-交接流程与启动指令.md` | 本文件 + 交接操作手册 |
| `docs-…/` | 主报告、交接文档、操作手册 |
| `patches-…/` | 补丁（基线 `<commit>`） |
| `tools-…/` | 可执行脚本 |
| `data-…/` | 原始核对数据 |
| `src-…/` | 源码副本（含 `.git`） |
| `MANIFEST-SHA256.txt` | 全量校验清单（正斜杠，`sha256sum -c` 可用） |

## 二、快速上手（3 步）
```bash
# 1) 读文档（按顺序）
# 2) 取源码（直接用包内副本 / 导入补丁）
# 3) 跑第一个验证命令
```

## 三、结论速查（30 秒）

- **候选/优先级**：…
- **别做**（浪费名额/会犯错）：…
- **已无线可捡的维度**：…

## 四、接手方必须知道的边界
1. …
2. …

## 五、范围边界：包含 / 未包含（重要）

**包含**：…

**未包含**：

| 缺什么 | 影响 | 怎么补 |
| --- | --- | --- |
| 完整 git 历史（若为浅克隆） | 不能考古/直接推全历史 | `git fetch --unshallow` |
| 子模块内容 | 相关功能不可用 | `git submodule update --init --recursive` |
| 只存在于会话上下文的原始记录 | 无法逐条追溯原始论证 | 按文档中的复核命令重跑 |
| 外部网页原文 | 只有 URL | 按链接重取 |
| 运行环境/实测数据 | 未实测 | 在 <环境> 上按 <手册> 执行 |

> ⚠️ 因此：**这个包是"本次工作产出 + 可离线开工的副本"，不是上游项目的完整快照。**

## 六、校验
```bash
sha256sum -c MANIFEST-SHA256.txt | tail -3
```

## 硬要求

- 第一节表格必须**与包内实际目录逐字一致**（改名后忘了同步是最常见的低级错误）。
- 第五节**不许省略**：接手方必须知道"哪些证据不在包里"。
- 全文禁止出现指向原会话的表述（"之前讨论过""如上所述"）。
