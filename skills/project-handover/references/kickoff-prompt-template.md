# 启动指令（kickoff prompt）写法规范

> 接手方**读不到你的会话**。启动指令是唯一能把"上下文、状态、禁令、验收"塞给它的载体。
> 六段缺一不可；缺哪段，接手方就会在哪一段上犯错。

## 六段结构

| 段 | 作用 | 写法要求 | 缺了会怎样 |
| --- | --- | --- | --- |
| `[角色]` | 定位项目与根目录 | 项目名 + **绝对路径** | 找错目录 / 读错项目 |
| `[第一步·必读]` | 阅读顺序 | 有序列表，**不许跳**，标注每份文件的用途 | 跳读 → 漏掉红线 |
| `[当前状态]` | 防误判 | 已完成什么、**什么是未验证的**、是否已对外提交 | 误以为已实测/已提交 |
| `[环境]` | 前置条件 | 机器/依赖/`source` 命令/算力窗口 | 一上机就报错 |
| `[按序执行]` | 行动清单 | **命令级可复制**，每条附判读标准（达标/不达标怎么办） | 空转、做无关的事 |
| `[硬性禁止]` | 防事故 | 未授权操作、已知失效做法、会产生无效提交的做法 | 乱 push / 重复提交无效项 |
| `[交付格式]` | 进展可验证 | 固定"命令 / 日志路径 / 结论 / 下一步"四件套 | 只报"做完了"，无法核验 |

> 实践上把 `[硬性禁止]` 与 `[交付格式]` 合成第六段即可，但两者都必须有。

## 模板

```text
[角色] 你是 <项目名> 的接手 AI。项目根目录：<绝对路径>
[第一步·必读] 依次读，不要跳：
1) <入口文件>            ← <它的用途>
2) <交接文档>            ← 任务规则、全部结论、红线、边界
3) <主报告>
4) <操作手册>
[当前状态] <已完成：…>；<未验证：…>；<未提交：…>
[环境] <机器/版本>，先执行 <前置命令>
[按序执行]
1) <命令>    —— <目的>；失败则 <降级方案>
2) <命令>
3) <命令>
4) <决策：按 <标准> 选择/排序>
5) <提交前检查：去重/模板/名额>
[硬性禁止]
- 未经确认不要 push / 不要改主干 / 不要开 PR
- 不要用 <已知失效的命令>
- 不要把 <A> 与 <B> 混为一谈（<为什么>）
[交付格式] 每步回报四件套：命令 / 原始日志路径 / 结论（达标或不达标）/ 下一步计划
```

## 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 只给包不给指令 | 接手方不知道先做什么 | 指令与包一起交付 |
| 状态段只写"已完成" | 误以为已实测/已提交 | 显式写"未验证 / 未提交" |
| `[按序执行]` 只写方向不写命令 | 接手方自由发挥 | 命令级可复制 + 判读标准 |
| 没有禁止段 | 未授权操作、无效提交 | 列出具体禁令与理由 |
| 用相对路径 | 接手方 CWD 不同 → 找不到 | 一律绝对路径 |
| 留 `<占位符>` 未替换 | 指令不可执行 | 交付前全文搜索 `<` 与 `<...>` |
