# 资源门禁（Resource Gate）— 接入后什么能自动做，什么必须先报批

> 对应 SKILL 的 **I2 / I9 / I10**。**接入 ≠ 立刻开工**：接入先把项目读清楚、整理好；真正的执行/计算/分析要过审批。

## 一、两阶段模型

| 阶段 | 内容 | 是否需要审批 |
| --- | --- | --- |
| **阶段 A · 自动**（资源无关） | 信息读取、项目整理：列清单、建目录、解包、校验格式与哈希、写索引/计划/记录、读文档与日志、轻量文本统计 | **不需要**，读完直接做 |
| **阶段 B · 待审**（资源相关） | 具体执行、计算、分析：编译构建、跑测试/基准/性能、训练/推理、占用设备、大规模数据处理、需要凭据或外部服务、修改外部系统 | **必须先汇报并获得审核通过** |

**默认从严**：判定不确定 → 归入阶段 B。

## 二、判定标准（三问，任一为"是"即阶段 B）

1. **是否需要特定机器能力？**（NPU/GPU、特定核数/内存、特定驱动或编译器、许可证、网络或外部服务）
2. **是否消耗不可忽略的资源或有副作用？**（长时间 CPU/IO、独占设备、写外部系统、删除/覆盖数据）
3. **换一台配置不同的机器，可行性或结论会变吗？**

## 三、分类表（可直接照用）

| 操作 | 阶段 | 说明 |
| --- | --- | --- |
| 列目录、读文件、`grep`、`wc`、`diff`、算文件哈希 | A | 纯读；小规模 |
| 解包归档、复制/移动（不删除源）、建目录 | A | 本地文件操作 |
| 格式校验、清单校验（`check_info_doc.py` / `verify_handover.sh`） | A | 读 + 比对 |
| 生成 `INDEX.md` / `registry.json` / `ACCESS.md` / 接入计划 | A | 写规划类文档 |
| 静态阅读代码/文档得出结论（不需要运行） | A | 不依赖设备 |
| 全量 SHA256 校验（GB 级、耗时分钟级） | A 偏 B | ＜1 分钟按 A；数据量大/耗时显著 → B |
| 编译/构建（`make`/`cmake`/`build.sh`） | **B** | 需要编译器/CANN/SDK；耗时耗核 |
| 跑测试、跑基准/性能/压测 | **B** | 占用设备与机时 |
| 训练、推理、算子执行、设备侧复现 | **B** | 独占 NPU/GPU |
| 大规模数据生成/处理/统计分析 | **B** | 资源占用不可忽略 |
| 需要凭据、付费 API、外部服务/网络下载 | **B** | 依赖外部配置与配额 |
| `git push` / 开 PR / 部署 / 发布 | **B** | 修改外部系统（不可逆） |
| 删除、覆盖、清空既有数据 | **B** | 不可逆 |
| "先跑一下看看" / 试探性执行 | **B** | 不因"很小"而豁免 |

## 四、审批单（必须逐项报告）

**写到哪里**：追加到 `<工作根>/APPROVALS.md`；同时在对应项目的 `ACCESS.md` 执行日志里留一行 `pending`。

```markdown
## [AR-001] <项目 project_id> — <一句话操作名>
- 状态：pending            <!-- pending | approved | rejected -->
- 提出时间：<ISO8601>
- 操作与命令：
  ```bash
  <可直接复制的完整命令>
  ```
- 为什么需要：<这一步要产出什么结论/产物，属于哪个未完成事项>
- 资源占用：设备=<NPU/GPU/无> 核数=<n> 内存=<n> 预计耗时=<n> 配额=<有无>
- 依赖的机器配置：<CANN 版本 / 驱动 / 编译器 / 网络 / 凭据 / 许可证>
- 风险与回滚：<失败会怎样；如何撤销；是否产生不可逆副作用>
- 预期产物：<文件/日志路径>
- 不执行的后果：<阻塞了什么；是否有替代的只读路径>
```

多项目同时申请时：**一张表汇总所有待审项**，把抢同一独占资源的项标出串行顺序。

## 五、执行纪律

1. **未获批 → 不执行**。不得因为"看起来没风险""只跑一次"而绕过。
2. **获批范围即边界**：命令、资源、时长、影响面超出获批范围 → 重新申请。
3. 获批后执行，回填四件套：**命令 / 日志路径 / 结论 / 下一步**。
4. 被拒 → 记录原因；除非条件变化，不要重复申请同一件事。
5. 阶段 A 的操作**不要**写进审批单（避免审批噪音）；只有阶段 B 才申请。

## 六、与"停问条件"的关系

SKILL 的 **I3**（不可逆操作 / 缺凭据 / 信息冲突 / 格式不合格）仍然独立适用；
**Resource Gate 是额外的、更宽的一道闸**——即使操作可逆、无凭据问题，只要依赖机器资源，也必须先审。

## 七、示例

| 场景 | 判定 | 原因 |
| --- | --- | --- |
| 读完 `HANDOVER.md` 后生成接入计划 | A | 纯整理 |
| 把 3 个包解到各自的 `project_id/` 目录 | A | 本地文件整理 |
| 按计划 `bash scripts/build.sh -b` | **B** | 需编译器/CANN，占机时 → 申请 |
| 跑 A/B 性能对照 | **B** | 占设备与配额，且结果依赖具体硬件 → 申请 |
| `git push` 修好的补丁 | **B** | 修改外部系统 → 申请 |
| 用 `grep` 统计日志里的错误条数 | A | 纯读；若日志 TB 级 → B |
